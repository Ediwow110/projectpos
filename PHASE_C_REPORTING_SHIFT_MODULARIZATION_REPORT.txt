REPORTING EXTRACTION
====================
New pure function revenueSeries(buckets, granularity, sales):
  - Prefills the caller-provided ordered day/hour UTC buckets with zero
    netRevenue and zero orders.
  - Uses existing bucketKey() (UTC calendar day/hour).
  - Adds sale.totalMinor - refunded per settled sale, one order each.
  - Ignores sales whose bucket does not exist in the supplied list.
  - Preserves requested bucket order, counts, refund subtraction, and results.
Call sites:
  ReportingService.getOverview() — daily revenue series.
  ReportingService.getSalesReport() — hourly or daily revenue series.
Intentionally kept:
  Billing feature gates; withScope tenancy; register and branch filters;
  report range/compare resolution; profit visibility; KPI computation; top
  products; generatedAt formatting; invoice/expense behavior; UI/API contracts.
Removed duplicated inline aggregation without moving DB reads or changing
report payload shapes.

SHIFT READ-MODEL EXTRACTION
===========================
New pure function selectShiftList(rows, opts, role, actorId):
  - Applies exact pre-existing status and register filters.
  - Restricts cashier list to shifts opened by that cashier, optionally
    including other cashiers' OPEN shifts as restricted close candidates.
  - Keeps closed shifts belonging to others invisible to cashiers.
  - Preserves descending shift-ID sort, cursor behavior (including missing
    cursor), page bounds (1..100; default 50), and nextCursor semantics.
  - Projects close candidates with only permitted fields, not complete
    DbShift rows.
  - Does not mutate input arrays.
Interfaces ShiftCloseCandidate and ShiftListItem were moved to shift-list.ts;
shift.service.ts re-exports them as types for existing callers.
ShiftService.listShifts retains its existing tenancy scope and DB call before
passing rows into the pure selection/projection layer.
No change was made to shift open/close/movement locking, cash counting,
corrections, post-close drift checks, manager approvals, or audit rows.

DEFERRED OBSERVATIONS (NOT ALTERED)
===================================
1. ReportingService.getPaymentsReport() passes query.registerId to
   ReportingCore.settledSales() but does NOT pass query.branchId, unlike
   getSalesReport(). When a branch-specific payment report is requested this
   may include other branches' settled sales. This is a potential functional
   filter inconsistency; it requires a separately scoped characterization test
   and bug-fix review, not a behavior-changing change during this refactor.
2. ReportingService.attentionFor() accepts branchId for inventory balances
   but counts open shifts, refund requests and unknown payments from the
   business-wide lists. Review intended dashboard alert scope before adjusting.
3. ReportingService.getCashReport() repeats the expected-cash arithmetic that
   also exists in shifts/cash.ts. This should be reconciled in a separate,
   test-first check if/when further cash-report edits are made.
These are code-review observations, not claims of reproduced production bugs.
