DESIGN/SAFETY VERIFICATION BY PHASE
==================================
Phase A — transaction safety:
  Refund normalization is isolated; lock, authorization, approval and
  transaction sequence remain in the refund service.
  The DbPort / PlatformPort source import loop uses type-only imports.
  Test coverage is scoped and does not certify production workflows.

Phase B — checkout:
  POS checkout online/offline lifecycle moved behind a testable flow contract.
  Redirect, unknown-payment reconciliation and provisional offline messages
  have focused coverage.
  KNOWN behavioral debt: offline pay() returns true even if offline queueing
  fails. It was preserved deliberately during refactor; fix separately with
  UI behavior tests, not as a silent change.
  Manager-approval retry integration requires live/UI characterization.

Phase C — reporting and shifts:
  Revenue bucket projections and cashier-safe shift list are pure modules.
  Reports and shift service regressions were verified in earlier phases;
  this turn reran their core new pure-module suites only.
  POTENTIAL functional defect to investigate with test-first scope:
  getPaymentsReport() omits branchId when requesting settled sales, unlike
  other reporting views. Dashboard attention counts may mix branch-specific
  inventory with business-wide alerts. Do not fix blindly without product
  decision on intended scope.

Phase D — frontend:
  Refund previews and submitted requests share one selection/calculation.
  Procurement receipt/return totals and CSRF request ordering have targeted
  tests.
  Dense JSX in supplier and PO pages remains. There were no screenshot
  comparisons or browser behavior tests in this release audit.

Phase E — adapter parity:
  Memory idempotency now encodes [businessId,key,commandType] as a tuple,
  avoiding delimiter collisions with colon-containing strings.
  PostgreSQL adapter assertions use a fake PgContext; they do NOT prove
  runtime PG integration/locking. Existing destructive PG tests must be
  run only on an independently verified disposable test database.
