BEHAVIOR-PRESERVATION MATRIX
============================
1. Empty cart: exact "Cart is empty." message and false checkout result.
2. Offline identity still loading: exact existing message.
3. Offline store missing: exact existing error message.
4. Offline discounted sale: still blocked by connectivity requirement.
5. Offline queue: still uses original queueOfflinePosSale, provisional receipt,
   identical cart/discount/tender/UI resets and exact success/failure text.
6. Offline runPosCheckout: still returns true following payOffline even if
   offline queuing fails; this odd legacy behavior was deliberately preserved,
   not silently changed. It merits a separately scoped UX bug report.
7. Resumed held sale while offline: still blocked before queuing.
8. Unavailable PayMongo method: still blocked with exact message.
9. Gift-card load with internal tender: still blocked.
10. Hosted PayMongo: still sets redirecting message and assigns checkout URL;
    never incorrectly marks a redirect as completed.
11. Payment UNKNOWN: still retains cart and exposes reconciliation payment ID
    and sale ID, preventing a blind repeat.
12. Completed sale: clears cart and pending draft, sets receipt ID, resets
    payment state, and shows "Sale completed."
13. One-time NEW gift-card codes: still surfaced only after completion.
14. API FORBIDDEN when discount is present: manager-approval callback retained
    with the same retry/approval-token signaling and error formatting.
15. Other API and generic errors: status text and false return preserved.
16. Paying state: enabled before online operation and reset in finally.
17. Payment result fields: cleared at the same places and in the same order.
18. Held-sale hold/resume logic and manager approval retry wrapper are
    still owned by the existing POS page controller.
