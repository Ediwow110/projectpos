CONFIRMED PARITY DEFECT
=======================
apps/api/src/common/memory/sales.family.ts previously encoded a claim
identifier as:
    businessId + ":" + key + ":" + commandType

This encoding is ambiguous when individual fields contain ':':
  Claim 1: ("business-1", "checkout:mobile", "sale.complete")
  Claim 2: ("business-1", "checkout", "mobile:sale.complete")

Memory generated the same concatenated key for these two DIFFERENT
tuples, rejecting claim 2 as IDEMPOTENCY_REPLAY. PostgreSQL treats these
as distinct because its unique constraint is on separate columns
("businessId", "key", "commandType").

This is a source-level, experimentally reproduced parity defect, not
evidence of a known production incident. Current production command
types may not include ':', but DbPort defines arbitrary string keys and
command types, so the delimiter encoding was not collision-safe.
