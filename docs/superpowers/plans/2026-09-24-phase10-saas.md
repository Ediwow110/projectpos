# Phase 10 SaaS Billing and Integrations Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Implement Phase 10 per `docs/superpowers/specs/2026-09-24-phase10-saas-design.md`: server-side entitlements with trials and grandfathering, billing ledger with idempotent webhooks, provider adapters, accounting exports, print queue, display feed, and scoped public API tokens — all prior suites green.

**Architecture:** Two new NestJS module families in the modular monolith (`BillingModule`, `IntegrationsModule`), zero new infrastructure, zero cron (time transitions resolve lazily per request). Entitlement enforcement lives inside domain services (authoritative, unit-testable); controllers only map the new `PLAN_LIMIT` code via the existing `statusFor` helper.

**Tech Stack:** TypeScript strict, Node 24, pnpm 9.15.9, Turborepo, NestJS 11 (REST, `/api/v1`), PostgreSQL 16, Prisma, Zod 3.23.8, Vitest 3.2.7, supertest, Next.js 15 + React 19 + TanStack Query. No new dependencies.

**Spec:** `docs/superpowers/specs/2026-09-24-phase10-saas-design.md`. PLAN.md (`G:\Vscode\PLAN.md`) is authoritative on conflicts, the spec second, this plan third.

## Global Constraints

- TypeScript strict end-to-end, integer minor units for money, integer quantities for stock, no float arithmetic.
- Tenant derived server-side from authenticated membership only; platform routes use `x-platform-key` bearer against `PLATFORM_API_KEY` env (never a tenant session).
- Every business-owned table includes businessId; all Phase 10 additions are additive (nullable or new tables) — prior behavior unchanged, proved by all prior suites staying green.
- API versioned `/api/v1`, error envelope `{ code, message, correlationId, fields? }`, ISO 8601 UTC, `X-Request-Id` correlation.
- `Idempotency-Key` required on webhook ingestion, token mint, print-job create, resolve-style mutations; uniqueness on `(businessId, key, commandType)`; fingerprint mismatch → `IDEMPOTENCY_MISMATCH`.
- Audit log append-only; platform actor recorded as `platform`.
- Cookie `pos_session` + `X-CSRF-Token` on mutations (public display feed and Bearer-token API excepted per spec); explicit `res.status(...)` on every POST.
- No card data anywhere; no real-money SDKs; no cron workers; no AI work.
- Every task follows TDD red-green-refactor, minimal code, frequent commits.

  if (!trialEndsAt) return null;

- **Per-request audit rows for token reads.** `apitoken.mint`/`apitoken.revoke` are audited; auditing
  every read would flood the log. Documented decision.
- **The `*.module.ts` files stay unused**, matching the pre-existing convention for every domain in
  this codebase (`AppModule` wires controllers/providers directly). Removing only the Phase 10 files
  would make the phase inconsistent with phases 0-9.
- **Prisma-backed `DbPort`.** Pre-existing, dated scaffold follow-up (documented in `app.module.ts`).
  The migration gate proves the SQL schema applies on real PostgreSQL even though the runtime uses
  the in-memory store.

### Second review round (fixes after the first pass)

1. **Canceled/paused subscriptions no longer keep their paid plan.** `resolvePlan` grants a plan
   only for `active`, `past_due` (grace), or an unexpired trial; anything else persists the Free
   plan and a `canceled` status so every reader agrees. Provider spellings are normalized
   (`cancelled` → `canceled`). Regression tests cover repeated resolution and a capped write after
   expiry.
2. **Every receipt setting key is gated.** The settings schema accepts `receiptHeader`/`receiptFooter`
   while the gate only matched `receipt`/`receipt.*`, so Free tenants could customize receipts. The
   gate now matches the whole `receipt*` family, and `PATCH /business/settings` returns the 402
   envelope with machine fields instead of a 500.
3. **Webhook signatures are verified over the exact request bytes** (`rawBody: true` on the Nest app),
   so providers that sign their own serialization are accepted; canonical JSON remains the fallback
   for non-HTTP callers. A failed delivery now releases its claim, so a transient failure can be
   redelivered instead of being stuck as an already-handled event.
4. **All invoice/subscription writers share the business lock**, and a period can only be billed
   once (an open or paid period returns the existing invoice; a voided one can be re-issued). A
   partial unique index backs this in SQL.
5. **Catalog imports are all-or-nothing**: capacity for the whole batch is checked inside one locked
   section, so an import that cannot fit leaves nothing behind.
6. **Monthly usage counts settled sales only**, and successful payment reconciliation meters the sale
   exactly once.
7. **Ledger accounting corrected**: change overpayment posts to 2200 Change Payable, inbound stock
   credits 7000 Inventory Receipts (never COGS), an empty export returns a header-only CSV, the audit
   row counts every emitted row, and CSV cells neutralize spreadsheet formulas.
8. **Receipts print subtotal, discount, and tax** so a discounted or taxed sale reconciles; covered by
   an integration test that queues a real discounted sale.
9. **Downgraded API tokens get a 402 with machine fields** (the guard forwards the entitlement error's
   fields through the shared filter), and a global flag route (`PATCH /api/v1/platform/flags`) makes
   the global flag rows manageable.
10. **The display feed uses indexed point reads** (latest sale for the register, shift existence)
    instead of loading the tenant's whole sales and shift history on every 5-second poll.
11. **Test-double provider scripts require a tenant** and have no global fallback.
12. **Printer responses no longer expose `agentTokenHash`**, and one shared `RequestError` component
    renders every plan-limit breach with its upgrade link (customers, expenses, reports, registers,
    branches, dashboard, billing).
13. The branch-cap concurrency test was replaced with a register-cap race that can actually be won,
    so it fails if the locking regresses.
